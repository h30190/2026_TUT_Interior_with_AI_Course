## 課程內容

### Part 1｜設計運算概念（講座前半，1hr）

**什麼是設計運算（Computational Design）**

- 不是「用電腦畫圖」，而是「用規則／演算法生成設計」
- 室設場景：
  - 空間布局自動化（家具擺放、動線）
  - 材料估算（依布局算用量）
  - 動線分析（行走距離、碰撞）
  - 照明／採光估算
- 3 種基本演算法（概念＋示意）：
  - Greedy packing：一個一個擺，擺得下就擺
  - Constraint satisfaction：滿足約束（不重疊、靠牆、朝向）
  - Genetic / 搜尋：隨機變異＋評分，跑多代取最佳
- 設計師的判斷 vs agent 的候選：agent 給候選，人決定
- 延續 1003/1017 原則：agent 寫的演算法也要驗（手算 2–3 筆）

**信任地圖（延續 1003）**

- 比較可信：版面、重複性工作、風格一致
- 必須驗：數字、尺寸、數量、「這樣可以用」
- 新增：演算法的「合理」需設計師判斷，agent 只給候選

### Part 2｜AGENT 示範（講座後半，1hr）

**示範流程（15 分鐘）：**

1. 拿 `demo/sample-room.json`（一間矩形房間＋家具清單）
2. 叫 OpenCode 寫一個「矩形房間家具自動擺放」JS 工具
   - 輸入：房間尺寸、家具清單（名稱、寬、深、可旋轉）
   - 演算法：greedy + 碰撞檢測（AABB）
   - 輸出：Canvas 視覺化 + 材料估算表
3. 學生抽 2–3 個案例手算驗證（位置、不重疊、用量）
4. 跑異常：家具比房間大、重複名稱、0 尺寸
5. 跑比較：不同演算法（greedy vs random）結果差異
6. 跑趨勢：家具數量增加時擺放成功率

**治理 10 分鐘：**

- 演算法不是真理：給候選，設計師決定
- 假資料的埋雷就是給學生練習的標靶
- 學生分析完要把發現寫進自己資料夾，commit＋push 到 fork＝交件

### Part 3｜黑克松：建設計運算小工具（3hr）

**核心產出：用 agent 建一個「設計運算小工具」**

候選題（由低到高，做出來為止）：

1. 空間布局：矩形房間家具自動擺放（greedy + 碰撞）
2. 材料估算：依布局算磁磚／地板用量（含損耗率）
3. 動線分析：兩點最短路徑、 furniture 碰撞
4. 照明估算：窗面積 vs 房間面積採光比
5. 自選：學生自己帶來的室設麻煩事

**工具形式：**

- 原則上 HTML 網頁小工具（接 1017 網頁應用方向）
- 開放其他解：Python 腳本、Node 腳本都可以
- 學生用 Antigravity＋OpenCode 讓 agent 寫，自己驗，存進自己 `學號_姓名/` 資料夾

**四段：**

1. **自測（30min）**：用自己的工具照假資料跑，先抓自己的
2. **交叉稽核（90min）**：跑對方工具、照假資料攻擊、每條發現一份報告（要截圖）；確認是 bug 就請對方當堂修
3. **修復＋回歸（45min）**：被稽核方修（大改前先 commit），稽核方重跑那個壞值確認
4. **收工（15min）**：雙方 commit＋push 到 fork＝交件

**規則：**

- 稽核方只寫自己資料夾；對方工具只跑不改
- 修復方：大改前先 commit；修完重跑稽核方的壞值確認
- 跑不動：也是稽核結果，記「跑不動＋原因」，找業師救環境
- bug 太多：全記錄、先修最嚴重 2 個，不追求全修

### Part 4｜簡報＋預告（1hr）

- 每人 2–3 分鐘：對方工具抓到什麼／自己被抓到什麼／最卡的地方
- 業師挑 1–2 個「全班共笑」或「全班共驚」的 bug 當場講（把 bug 變案例）
- 預告 1219：收斂期末題目；無作業，push 到 fork 即交件

## 附錄：常見問題（課上隨查）

| 症狀 | 對策 |
| --- | --- |
| 演算法擺放失敗 | 檢查房間尺寸、家具尺寸、旋轉設定；先跑 greedy 簡化版 |
| 碰撞檢測錯 | AABB 只適用軸對齊矩形；旋轉後需 SAT 或分離軸 |
| 對方工具跑不動 | 報告記「跑不動＋原因」，也是結果；環境找業師 |
| bug 多到修不完 | 全記錄、先修最嚴重 2 個 |
| 不會修 | 請 owner 叫 OpenCode（「修擺放失敗的 bug」），但 owner 必須自己驗 |
| 截圖要求 | 輸入＋結果同屏可見；存自己資料夾 `screenshots/` |
| 單位混淆（最常見） | 報告標明單位：m² 或坪、m 或 cm |
| 對方工具沒抓到 bug | 加更狠攻擊（極大值、非數字、空白、超大家具）；還沒抓到→報告記「通過」，也值得講 |
