## 課程內容

### Part 1｜資料分析的幾種方式（講座前半，1hr）

4 種分析方式全教，每種配室內設計場景：

| 分析方式 | 室內設計場景 | 學生要做的 |
|---|---|---|
| 描述性統計 | 一批材料單價的均值、中位數、極端值 | 算出「這批報價有沒有離群的」 |
| 比較分析 | 同一材料、不同供應商的價格／規格比較 | 找出最划算的那家 |
| 異常偵測 | 規格表裡哪筆明顯偏離 | 標出來、寫原因 |
| 趨勢分析 | 材料價格走勢、用量走勢 | 畫一條線、講趨勢 |

**教學重點（接 1003）：**
- 1003 教「抓 bug」，1017 升級到「用數據說話」
- agent 寫的分析代碼**也要驗**（延續 1003 原則）：agent 算出的均值、極端值，學生抽兩三筆手算對一下，確認 agent 沒算錯
- 假資料 `demo/sample-specs.csv` 埋了 4 種雷，學生跑分析時要能抓出來：
  - 離群單價（磁磚 30x60 有一筆 500，其他 50–80）
  - 重複規格（同一材料多家供應商）
  - 負數／0 用量（壁布用量 0、木地板用量 −5）
  - 單位混用（玻璃一筆寫「坪」，其他 m²）

### Part 2｜AGENT 分析＋示範（講座後半，1hr）

**示範流程（10 分鐘）：**
1. 拿 `demo/sample-specs.csv`，叫 OpenCode 寫分析腳本（Python 或 JS）
2. 跑描述性統計：均值、中位數、極端值
3. 學生抽兩三筆手算驗證 agent 的計算（接 1003「自我檢查不叫驗證」）
4. 跑異常偵測：標出離群單價、負數用量、單位混用
5. 跑比較分析：同一材料多家供應商，找最划算的
6. 跑趨勢分析：畫走勢線

**治理 10 分鐘：**
- 假資料的埋雷就是給學生練習的標靶，不是要他們修
- 學生分析完要把發現寫進自己資料夾，commit＋push 到 fork＝交件

### Part 3｜黑克松：建重複規格分析工具（3hr）

**核心產出：用 agent 建一個「重複規格分析工具」**

- 輸入：一堆規格資料（CSV）
- 工具做：去重、按材料分組、統計每組的供應商數、價格區間、極端值
- 產出：一張表或一張圖（哪組材料供應商最多、哪組價格離群）

**工具形式：**
- 原則上 HTML 網頁小工具（接 1003 網頁應用方向）
- 開放其他解：Python 腳本、Node 腳本都可以
- 學生用 Antigravity＋OpenCode 讓 agent 寫，自己驗，存進自己 `學號_姓名/` 資料夾

**四段：**
1. **自測（30min）**：用自己的工具照假資料跑，先抓自己的
2. **交叉稽核（90min）**：跑對方工具、照假資料攻擊、每條發現一份報告（要截圖）；確認是 bug 就請對方當堂修
3. **修復＋回歸（45min）**：被稽核方修（大改前先 commit），稽核方重跑那個壞值確認
4. **收工（15min）**：雙方 commit＋push 到 fork＝交件

**規則：**
- 稽核方只寫自己資料夾；對方工具只跑不改
- 修復方：大改前先 commit；修完重跑稽核方的壞值確認
- 跑不動：也是稽核結果，記「跑不動＋原因」，找業師救環境
- bug 太多：全記錄、先修最嚴重 2 個，不追求全修

### Part 4｜簡報＋預告（1hr）

- 每人 2–3 分鐘：對方工具抓到什麼／自己被抓到什麼／最卡的地方
- 業師挑 1–2 個「全班共笑」或「全班共驚」的 bug 當場講（把 bug 變案例）
- 預告 1121：含 Revit 外掛 1 次（主 repo 排程標「待定」）

## 附錄：常見問題（課上隨查）

| 症狀 | 對策 |
|------|------|
| 對方工具跑不動 | 報告記「跑不動＋原因」，也是結果；環境找業師 |
| bug 多到修不完 | 全記錄、先修最嚴重 2 個 |
| 不會修 | 請 owner 叫 OpenCode（「修單價離群的 bug」），但 owner 必須自己驗 |
| 截圖要求 | 輸入＋結果同屏可見；存自己資料夾 `screenshots/` |
| 單位混淆（最常見） | 報告標明單位：m² 或坪、m 或 cm |
| 對方工具沒抓到 bug | 加更狠攻擊（極大值、非數字、空白）；還沒抓到→報告記「通過」，也值得講 |
