# skill 使用稽核

回答一個問題：**我養的這些 skill，哪些真的在用？**
但它不會直接告訴你「刪這個」，因為零次有四種完全不同的原因，處置相反。

## 跑法

```bash
node scripts/稽核.js          # 人看的報告
node scripts/稽核.js --json   # 給程式吃的
node scripts/測試.js          # 改過解析邏輯後必跑
```

## 資料來源與它們的極限

| 來源 | 內容 | 極限 |
|---|---|---|
| `~/.claude/projects/**/*.jsonl` | Claude 的 `Skill` 工具呼叫 | 只有 D--Claude 這個專案、2026-07-13 之後；換機或清掉逐字稿就沒了 |
| `~/.openclaw/state/openclaw.sqlite` 的 `skill_usage` 表 | 龍蝦的用量 | 2026-09-19 實測**整張表 0 筆**，龍蝦端等於沒有資料 |
| `~/.claude/skills`、`D:/Claude/skills` | 清單、description、是否符號連結 | — |
| `D:/Claude/CLAUDE.md`、`AGENTS.md` | 路由表有沒有指名這個 skill | — |

**只有「Skill 工具被顯式呼叫」會被算成一次。**skill 名字出現在對話文字裡不算——
路由表每個 session 都會被注入，天真的字串比對會把 `interior-boq-quote` 算成 216 次。
`測試.js` 有一條測試專門守這件事。

## 分類怎麼讀

| 類別 | 意思 | 處置 |
|---|---|---|
| 活躍 | 30 天內用過 | 留著 |
| 低頻但常回來 | 累計 3 次以上，但最近沒用 | 留著 |
| 低頻 | 用過 1–2 次 | 留著，再觀察 |
| 零次但路由表有指名 | CLAUDE.md／AGENTS.md 明寫要用它，實際卻沒被呼叫 | **修觸發條件，不是刪** |
| 零次但看起來是季節性 | description 含交屋、保固、口試這類低頻情境字眼 | 留著，等那個季節到再評估 |
| 零次且是外部連結 | 符號連結到 `~/.agents/skills` 等共用來源 | 刪連結不等於刪 skill，先查來源歸誰管 |
| 零次且無人指名 | 沒用過，路由表也沒提到它 | 可刪候選，你確認後**手動**刪 |
| 無用量資料 | 該來源根本沒有資料可查 | 不能判斷，先別動 |

## 判斷零次時要先問的三件事

1. **這件事你最近做過嗎？**做過但顯示零次 → 工作被直接做掉、沒走 skill。
   問題在觸發條件或路由表，刪掉只會讓下次更沒章法。
2. **它是不是一年才用一次？**交屋手冊、保固通知、口試準備本來就低頻，
   用兩個月的資料判它死刑不合理。
3. **路由表把它換掉了嗎？**例如 `interior-vendor-db` 目前零次且無人指名，
   因為 CLAUDE.md 已改成走 company-tools MCP 的 `vendor_search`。
   這種是真的功成身退，可以刪——但要確認 MCP 真的涵蓋了原本的功能。

## 邊界

- **只讀不刪。**這支腳本不會動任何 skill 檔案，刪除一律由 Jason 手動執行。
- **`D:/Claude/skills` 是龍蝦的地盤**，這裡只讀取與列出，不得修改或刪除。
- 樣本太少時不要硬給結論。2026-09-19 首次執行時，兩個月內全部只有 4 次呼叫紀錄，
  這種樣本量撐不起刪除決策——要有把握的話得先讓用量資料累積起來。
