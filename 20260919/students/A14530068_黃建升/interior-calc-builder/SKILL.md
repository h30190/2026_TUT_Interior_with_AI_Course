# 室設單檔計算機產生器

南應室設 115-1「設計運算與 AI 整合應用」第一堂（2026-09-19）黑克松產出。

室內設計的估算有個共同結構：**幾個現場量到的數字 → 一條有假設的公式 → 一個要拿去下單的數量**。
重複的是結構，不是公式。所以這個 skill 把結構交給腳本，只留兩件事給人：
**公式對不對**，以及**預設值合不合實務**。

## 分工原則

能寫成腳本的一律寫成腳本。判斷留給人。

| 工作 | 誰做 |
|---|---|
| 算數、產生 HTML、檢查規格 | 腳本，零 AI |
| 公式怎麼列、參數預設值多少、驗算案例用哪組數字 | 人 |

**不要手寫或手改產出的 HTML。**要改就改設定檔或 `scripts/公式.js`，然後重跑產生器。
手改過的檔案下次重跑就被蓋掉，而且繞過了所有檢查。

## 四支腳本

```bash
node scripts/公式.test.js                      # 驗計算引擎本身
node scripts/建立計算機.js 設定/油漆用量.json     # 設定檔 → 單檔 HTML
node scripts/檢查.js ../油漆用量計算機.html       # 驗產出是否合規
```

| 檔案 | 職責 |
|---|---|
| `scripts/公式.js` | 計算引擎，Node 與瀏覽器共用同一份。契約：`計算(名稱, 輸入) → { 過程, 值, 註記 }` |
| `scripts/公式.test.js` | 引擎的測試案例，預期值手算寫死。改公式後必跑 |
| `scripts/建立計算機.js` | 設定檔 → 單檔 HTML。產生前先擋掉危險 id、缺漏欄位、沒有驗算案例的設定 |
| `scripts/檢查.js` | 產出檢查器。會用假 DOM 無頭跑一次頁面程式，抓得到「公式對但沒接上輸入欄」 |

## 硬性輸出規格

產出必須同時滿足下面五條，`檢查.js` 會逐條驗，缺一條 exit 1：

1. **單一 HTML 檔**：不連任何 CDN。雙擊就能開，工地沒網路也能用。
2. **顯示計算過程**：不能只吐一個答案。這個數字要拿去跟業主或工班對話，對方會問「怎麼算的」。
3. **假設要看得見而且可改**：塗佈率、損耗率、打摺倍數這類會因廠商而異的參數，一律是輸入欄，不准寫死。
4. **內含自動驗算**：載入時跑固定測試案例，畫面顯示通過或失敗。
5. **手機可用**：工地是用手機開的。

## 流程

### 第 1 步：把需求問清楚（對應「給情境」原則）

動手前確認四件事，缺哪一項就直接問，不要猜：

- **要算出什麼**：公升數？片數？碼數？這決定 `結果.欄位`。
- **現場能量到什麼**：使用者手上真正有的數字，不要設計一個需要他回工地重量的輸入。
- **哪些參數會變**：這些進 `參數`，不進 `輸入`。
- **驗算案例**：請他給一組「我知道答案」的實例。沒有這組數字就沒有驗算，產生器會直接拒絕。

### 第 2 步：公式進引擎，不進 HTML

先查 `references/公式與單位.md` 有沒有這類計算，再查 `scripts/公式.js` 有沒有實作。

- **有**：直接用，跳到第 3 步。
- **沒有**：先在 `references/公式與單位.md` 新增一節（公式、參數意義、預設值、預設值的來源與適用範圍），
  再到 `scripts/公式.js` 實作，然後到 `scripts/公式.test.js` 加測試案例。

**測試的預期值一律手算求得，不准從程式輸出回填**——回填的測試只是在複誦程式，永遠會過。
手算對不上就不要寫程式，這時候錯的是公式。

```bash
node scripts/公式.test.js
```

### 第 3 步：寫設定檔，跑產生器

在 `設定/` 下新增一份 JSON，照 `設定/油漆用量.json` 的格式。欄位的 `id` 就是公式的參數名。

```bash
node scripts/建立計算機.js 設定/你的計算機.json
```

產生器會先擋掉：危險 id、沒有預設值的欄位、驗算案例缺欄位、結果欄位不存在、沒有驗算案例。
被擋下來時看錯誤訊息改設定檔，不要繞過。

### 第 4 步：驗（對應「agent 會錯」原則）

先跑機器檢查：

```bash
node scripts/檢查.js ../你的計算機.html
```

全過之後**仍然要人工看兩件事**，這兩件腳本驗不了：

- 用瀏覽器實際打開，手動改一個跟驗算案例不同的數字，確認結果會跟著動而且量級合理。
- 縮到手機寬度看排版。

驗算失敗時，先確認是公式錯還是設定錯，**不要改預期值去迎合程式**——那是把溫度計砸了。

### 第 5 步：留痕（對應「可追溯」原則）

截一張跑起來的圖存同資料夾，把設定檔、公式、產出一起 commit。
commit 訊息寫清楚這個計算機算什麼、用了什麼假設。

## 邊界

- **產出估算工具，不產出報價單**。要正式報價單走 `interior-boq-quote`，那邊有單價庫和格式規範。
- **算出來的數字是估算，不是下單量**。這句話固定寫在輸出區，`檢查.js` 會驗它還在不在。
- **業主的平面圖、地址、姓名不准寫進設定檔或產出**。這些檔案會 commit 進公開 repo。

## 常見陷阱

**輸入欄的 id 不要取跟瀏覽器內建物件同名的字。**
`open`、`name`、`top`、`status`、`length`、`location`、`history` 這些在 `window` 上已經存在，
撞名會讀到內建物件而不是輸入框，整頁算出 NaN。
產生器與檢查器都有這份清單，前者拒絕產生、後者標記失敗。

**只驗公式的測試會漏掉接線錯誤。**
2026-09-19 實際踩到：公式測試兩組全過，但畫面全是 NaN——因為測試自己建輸入物件，
沒有經過讀取輸入欄那段。所以驗算固定有兩種：一個驗公式算得對不對，一個驗畫面有沒有接上。

**`檢查.js` 的無頭 DOM 不會重現瀏覽器的變數遮蔽行為。**
撞名這一關靠的是它的靜態 id 比對，不是無頭執行。兩道檢查各抓各的，不要因為其中一道過了就砍掉另一道。

**除數與比例一律要驗，而且只認一種壞值等於沒認。**
2026-09-19 第三方稽核抓到：塗佈率填 0 會算出 `Infinity 加侖`、損耗率填負數會算出負的用量、
坪數填負數會算出 `NaN`——三個都照常顯示在畫面上。更糟的是我的渲染檢查只比對 `NaN`，
所以整頁寫著 `Infinity 加侖` 時它還報通過。

現在規則集中在 `scripts/公式.js` 的 `規則` 物件，驗證不過時 `計算()` 回傳
`{ 錯誤: [...] }` 且值為空，頁面顯示「輸入有誤」與具體原因。
`檢查.js` 的壞值清單是 `NaN`／`Infinity`／`undefined`／`輸入有誤`，四種都擋。
新增公式時**一定要在 `規則` 裡補上該公式的除數與比例欄位**，否則就是重蹈這個坑。

## 錯誤要怎麼跳（2026-10-03 定案）

錯誤物件一律是 `{ 欄位, 等級, 訊息 }`，**帶欄位名才能標到出錯的那一格**。
只給訊息字串的話，使用者要自己從七個輸入欄猜，手機上尤其痛苦。

| 等級 | 什麼情況 | 畫面行為 |
|---|---|---|
| 錯誤 | 算不出來或結果無意義 | 該欄紅框＋紅字，結果顯示 `—`，計算過程清空 |
| 提醒 | 算得出來但可疑（地坪 0、損耗率 0） | 該欄黃字，**結果照常顯示** |
| 致命 | 公式不存在、計算拋例外 | 顯示「工具故障」＋請回報，不要假裝還能用 |

四條規則：

1. **錯誤標在出錯的欄位旁邊**，不是只在頁尾。工地是用手機看的。
2. **絕不留上一次的數字。**陳舊數字看起來像新算的，是假自信的來源。
3. 結果區只放一行總結（「2 個欄位要修正」），細節在欄位旁邊。
4. 修好即時消失，不用按按鈕。

溢位訊息要指路：講「超出範圍」沒用，室設最常見的溢位原因是單位填錯
（窗寬 300 公分填成 300 公尺），訊息直接點名這件事。

**一律用 CSS class 不用 inline style**——class 無頭測試驗得到，style 驗不到。
同理 `檢查.js` 的假 DOM 要給 `style: {}`，否則頁面一用 `el.style.x` 就拋錯，
看起來像頁面壞了，其實是假 DOM 不夠忠實。2026-10-03 實際踩到一次。

**底部「引擎自我測試」與當下輸入無關**，標籤要寫清楚。
否則上面紅字、下面綠字會被誤讀成自相矛盾的「假通過」。

## 三層防線，缺一層都會再犯

| 層 | 做什麼 | 為什麼不能省 |
|---|---|---|
| 入口 | `規則` 驗每個欄位的型別與範圍 | 訊息具體，使用者知道改哪裡 |
| 出口 | 回傳前掃 `值`，非有限數一律轉錯誤 | 有限的輸入相乘仍可能溢位，入口擋不住；**新增公式自動適用** |
| 掃描 | `壞值掃描.test.js` 矩陣式逐格掃 | 前兩層修的是這次的 bug，這層修的是「下次沒人想到要測」 |

2026-10-03 的實證：`公式.test.js` 15 組全綠、產出檢查 11 項全綠、第三方稽核也沒抓到，
卻被壞值清單掃出 11 個欄位填極大值會算出 Infinity。**不是我變聰明了，是因為有一份清單。**

## 產生器防呆（2026-10-03 暴力測試後補強）

設定檔是產生器的唯一輸入，所以它也是唯一的攻擊面。當時 20 個惡意設定有 12 個被接受。

**結構性錯誤一律拒絕產生**：重複的欄位 id、空的預期答案、缺結果單位或欄位、
沒有驗算案例、驗算案例缺欄位、欄位沒預設值、id 與瀏覽器內建撞名、公式不存在、
標題超長、**設定宣告的欄位沒蓋住公式需要的全部輸入**、
**檔名含 `..` 或路徑分隔符**（實證會寫到指定資料夾之外）。

其中「空的預期答案」最該擋——沒有任何預期值的驗算案例，
會產出一個永遠顯示「通過」的假驗算，比沒有驗算更糟。

**文字一律逸出，但不拒絕**。標題寫 `<b>` 是合法內容，該做的是逸出不是擋掉。
`逸出()` 處理 HTML 文字區，`安全JSON()` 把內嵌 JSON 的 `<` 轉成 `<`——
因為即使在 JS 字串裡，`</script>` 也會被 HTML 解析器當成結束標籤。

**判斷注入有沒有成功，要執行它，不要比對文字。**
逸出後的 JSON 字串裡照樣看得到那串注入文字，但它是資料不是程式碼。
`設定防呆.test.js` 的做法是把產出的 script 區塊實際跑一次，看全域變數有沒有被設。
2026-10-03 我用「文字有沒有出現在 script 區塊裡」判定，得到假陽性。

## 檢查器補的兩個盲點

**外部資源不能只看 `src`／`href`。**CSS 的 `@import url("https://…")` 一樣會連外，
稽核就是用這個穿過去的。現在三種形式都掃。

**輸入欄有沒有綁事件，要用行為判定。**頁面載入時 `render()` 會跑一次，
所以事件沒綁、畫面照樣是對的，只是改數字不會重算——光看畫面看不出來。
假 DOM 現在記下每個 input 收到的 `addEventListener`，用這個判定而不是比對原始碼。

## 單位用程式處理，不要用標籤文字

這個工具混用公尺、公分、公釐、坪。單位填錯是最容易發生也最難發現的錯——
**數字看起來完全正常，只是差 100 倍。**所以單位相關的東西一律寫成程式：

**換算表是程式不是文件**：`單位表` 以每個維度的基準單位為 1，用 `換算到(值, 從, 到)` 呼叫。
跨維度或不認得的單位一律拋錯，不回傳 NaN——那是寫程式的人錯了，不是使用者輸入錯。

**欄位宣告自己的單位與合理範圍**：`規則` 裡的 `單位` 與 `合理`。
值落在範圍外時試算常見誤填倍率，給出可行動的提醒：
「窗寬 3 cm 超出常見範圍；若這是公尺的數字，應填 300 cm」。
這是提醒不是錯誤，不擋計算——但結果區也會標示「⚠ N 項提醒」並轉黃，
因為只在欄位旁放小黃字的話，畫面中央仍是一個 28px 的大數字，那就是假自信的形狀。

**設定檔標籤與引擎單位要對得上**：`單位.test.js` 會檢查標籤文字有沒有提到該單位。
標籤寫「公分」但引擎當公尺算，會悄悄差 100 倍，而且所有數值測試都驗不出來。

### 台尺不要寫成 0.303

2026-10-03 單位測試抓到我自己的錯：表裡 `台尺 = 0.303`、`坪 = 3.305785`，
但坪的定義就是 6 台尺見方，`(6 × 0.303)² = 3.305124` 對不起來，**單位表自己跟自己矛盾**。
精確值是 `10/33` 公尺，坪是 `400/121` m²，才是 1 台尺見方。
講話說「一台尺 30.3 公分」沒問題，那是口語的四捨五入；
程式內部一律用精確值，否則換算鏈越長誤差越大。

這個錯只有把單位寫成程式、而且寫了「坪 = 6 台尺見方」這條自洽測試才會被發現。
寫在文件表格裡的話，兩個數字各自看都對，永遠不會有人去乘乘看。

## 可自選單位（2026-10-03）

設定檔的欄位加 `可選單位` 就會長出下拉選單，例如：

```json
{ "id": "ping", "標籤": "地坪（坪）", "可選單位": ["坪", "m2", "才"] }
```

三條設計原則：

**公式只認基準單位。**基準單位來自引擎的 `規則`，不是設定檔——公式吃什麼單位由公式決定，
設定檔只能決定「讓使用者可以選哪些」。換算只發生在讀值的那一個地方，公式完全不知道介面上有選單。

**換單位要換數值，不是重新詮釋同一個數字。**300 公分切成公尺要變成 3，不是維持 300。
後者正是差 100 倍的來源。

**每個欄位另外記一份基準單位下的值，畫面數字只是它的呈現。**
換單位一律從基準值換算，不從上一個顯示值接著換——否則修整誤差會累積，
實測 坪→才→m²→坪 繞一圈會從 10 變成 9.9999999。修整用有效位數（`toPrecision(8)`）
不用小數位數，否則 360 會顯示成 359.999997，很小的值（公釐、填縫）又會被截成 0。

產生器會擋：宣告了可選單位但引擎沒定義基準單位、可選單位不含基準單位、
可選單位與基準單位不同維度（例如長度換面積）。

### 才有三種，不要混

查證後確認（[1 才是多大](https://uptogo.com.tw/科學/1才是多大？/)）：

| 名稱 | 定義 | 用在哪 |
|---|---|---|
| 面積才 | 1 台尺 × 1 台尺 = 918.27 cm² | 玻璃、鋁窗、窗簾、板材計價 |
| 材積才 | 1 台寸 × 1 台寸 × 10 台尺 | 角材、木料 |
| 板材才 | 1 台尺 × 1 台尺 × 1 台寸 | 與材積才等值（都是 100 立方台寸） |

單位表裡 `才` 是面積才，`材積才` 是體積，兩者分屬不同維度所以換算會直接拋錯——
這是刻意的，混用才是真正的風險。

完整台製單位鏈：`1 分 = 0.3 cm`、`1 寸 = 10 分`、`1 尺 = 10 寸`、`1 丈 = 10 尺`、`1 坪 = 36 才`。
最後那條是很好的自洽檢查，`單位.test.js` 有驗。

### 改了實作就要回頭看第三方稽核

這次重構打壞了 `稽核.test.js` 兩條，原因不同，處理方式也不同：

- **我的 bug**：事件綁定用 `el.id` 反查欄位名，但假 DOM 的元素沒有 `id` 屬性。
  改成綁定時把欄位名閉包進去。**這是修程式。**
- **它的錨點**：那條測試用字串比對找「綁定那一行」，我改寫後字串不存在了。
  只更新錨點字串，**斷言完全沒動**。改的時候在檔案裡註明日期與理由。

分清楚這兩種很重要。前者是程式錯了，後者是測試找不到目標——
但絕不能因為第二種存在，就把第一種也當成「測試過時」帶過去。
