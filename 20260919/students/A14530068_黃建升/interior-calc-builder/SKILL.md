# 室設單檔計算機產生器

南應室設 115-1「設計運算與 AI 整合應用」第一堂（2026-09-19）黑克松產出。

室內設計的估算有個共同結構：**幾個現場量到的數字 → 一條有假設的公式 → 一個要拿去下單的數量**。
重複的是結構，不是公式。所以這個 skill 把結構交給腳本，只留兩件事給人：
**公式對不對**，以及**預設值合不合實務**。

## 分工原則

能寫成腳本的一律寫成腳本。判斷留給人。

| 工作 | 誰做 |
|---|---|
| 算數、產生 HTML、檢查規格 | 腳本，零 AI |
| 公式怎麼列、參數預設值多少、驗算案例用哪組數字 | 人 |

**不要手寫或手改產出的 HTML。**要改就改設定檔或 `scripts/公式.js`，然後重跑產生器。
手改過的檔案下次重跑就被蓋掉，而且繞過了所有檢查。

## 四支腳本

```bash
node scripts/公式.test.js                      # 驗計算引擎本身
node scripts/建立計算機.js 設定/油漆用量.json     # 設定檔 → 單檔 HTML
node scripts/檢查.js ../油漆用量計算機.html       # 驗產出是否合規
```

| 檔案 | 職責 |
|---|---|
| `scripts/公式.js` | 計算引擎，Node 與瀏覽器共用同一份。契約：`計算(名稱, 輸入) → { 過程, 值, 註記 }` |
| `scripts/公式.test.js` | 引擎的測試案例，預期值手算寫死。改公式後必跑 |
| `scripts/建立計算機.js` | 設定檔 → 單檔 HTML。產生前先擋掉危險 id、缺漏欄位、沒有驗算案例的設定 |
| `scripts/檢查.js` | 產出檢查器。會用假 DOM 無頭跑一次頁面程式，抓得到「公式對但沒接上輸入欄」 |

## 硬性輸出規格

產出必須同時滿足下面五條，`檢查.js` 會逐條驗，缺一條 exit 1：

1. **單一 HTML 檔**：不連任何 CDN。雙擊就能開，工地沒網路也能用。
2. **顯示計算過程**：不能只吐一個答案。這個數字要拿去跟業主或工班對話，對方會問「怎麼算的」。
3. **假設要看得見而且可改**：塗佈率、損耗率、打摺倍數這類會因廠商而異的參數，一律是輸入欄，不准寫死。
4. **內含自動驗算**：載入時跑固定測試案例，畫面顯示通過或失敗。
5. **手機可用**：工地是用手機開的。

## 流程

### 第 1 步：把需求問清楚（對應「給情境」原則）

動手前確認四件事，缺哪一項就直接問，不要猜：

- **要算出什麼**：公升數？片數？碼數？這決定 `結果.欄位`。
- **現場能量到什麼**：使用者手上真正有的數字，不要設計一個需要他回工地重量的輸入。
- **哪些參數會變**：這些進 `參數`，不進 `輸入`。
- **驗算案例**：請他給一組「我知道答案」的實例。沒有這組數字就沒有驗算，產生器會直接拒絕。

### 第 2 步：公式進引擎，不進 HTML

先查 `references/公式與單位.md` 有沒有這類計算，再查 `scripts/公式.js` 有沒有實作。

- **有**：直接用，跳到第 3 步。
- **沒有**：先在 `references/公式與單位.md` 新增一節（公式、參數意義、預設值、預設值的來源與適用範圍），
  再到 `scripts/公式.js` 實作，然後到 `scripts/公式.test.js` 加測試案例。

**測試的預期值一律手算求得，不准從程式輸出回填**——回填的測試只是在複誦程式，永遠會過。
手算對不上就不要寫程式，這時候錯的是公式。

```bash
node scripts/公式.test.js
```

### 第 3 步：寫設定檔，跑產生器

在 `設定/` 下新增一份 JSON，照 `設定/油漆用量.json` 的格式。欄位的 `id` 就是公式的參數名。

```bash
node scripts/建立計算機.js 設定/你的計算機.json
```

產生器會先擋掉：危險 id、沒有預設值的欄位、驗算案例缺欄位、結果欄位不存在、沒有驗算案例。
被擋下來時看錯誤訊息改設定檔，不要繞過。

### 第 4 步：驗（對應「agent 會錯」原則）

先跑機器檢查：

```bash
node scripts/檢查.js ../你的計算機.html
```

全過之後**仍然要人工看兩件事**，這兩件腳本驗不了：

- 用瀏覽器實際打開，手動改一個跟驗算案例不同的數字，確認結果會跟著動而且量級合理。
- 縮到手機寬度看排版。

驗算失敗時，先確認是公式錯還是設定錯，**不要改預期值去迎合程式**——那是把溫度計砸了。

### 第 5 步：留痕（對應「可追溯」原則）

截一張跑起來的圖存同資料夾，把設定檔、公式、產出一起 commit。
commit 訊息寫清楚這個計算機算什麼、用了什麼假設。

## 邊界

- **產出估算工具，不產出報價單**。要正式報價單走 `interior-boq-quote`，那邊有單價庫和格式規範。
- **算出來的數字是估算，不是下單量**。這句話固定寫在輸出區，`檢查.js` 會驗它還在不在。
- **業主的平面圖、地址、姓名不准寫進設定檔或產出**。這些檔案會 commit 進公開 repo。

## 常見陷阱

**輸入欄的 id 不要取跟瀏覽器內建物件同名的字。**
`open`、`name`、`top`、`status`、`length`、`location`、`history` 這些在 `window` 上已經存在，
撞名會讀到內建物件而不是輸入框，整頁算出 NaN。
產生器與檢查器都有這份清單，前者拒絕產生、後者標記失敗。

**只驗公式的測試會漏掉接線錯誤。**
2026-09-19 實際踩到：公式測試兩組全過，但畫面全是 NaN——因為測試自己建輸入物件，
沒有經過讀取輸入欄那段。所以驗算固定有兩種：一個驗公式算得對不對，一個驗畫面有沒有接上。

**`檢查.js` 的無頭 DOM 不會重現瀏覽器的變數遮蔽行為。**
撞名這一關靠的是它的靜態 id 比對，不是無頭執行。兩道檢查各抓各的，不要因為其中一道過了就砍掉另一道。
